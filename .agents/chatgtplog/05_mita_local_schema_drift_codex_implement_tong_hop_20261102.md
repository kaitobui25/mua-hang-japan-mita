Sau khi chốt kế hoạch, người dùng yêu cầu `/implement` toàn bộ kế hoạch. Cuối phiên yêu cầu ghi tổng kết vào `chatgtplog`.

Vì thế query login thật vẫn lỗi SQLSTATE **42703** và Desktop tiếp tục thấy HTTP 500. Bài học: **test pass không đồng nghĩa database thật đã migrate**, `/api/health` chỉ `SELECT 1` và HTTP 200 không chứng minh từng API Admin chạy được.
- Sau khi xác nhận đích, sao lưu và `pg_restore` thử, đã áp dụng **phần DDL xác thực riêng** từ `backend/src/db/admin.sql` trong transaction local, `COMMIT` thành công: bổ sung cột/constraint/index, tạo Staff limiter, đặt username Owner là `owner`; bảo toàn Owner ID/password hash/timestamp/session/limiter. Không reset mật khẩu, không chạy migration tổng, không đăng nhập bằng mật khẩu Owner thật.
- Desktop vẫn hiển thị chuỗi thông báo tổng quát **“Admin API HTTP 500. 400: invalid input; 401: login required; ...; 5xx: backend error. No write retry.”**. Log backend thực tế chỉ ra `GET /api/admin/notifications`, `/pricing`, `/products` trả 500, còn `/orders` và `/api/health` 200. Do đó đây là **lỗi schema tiếp theo**, không phải bằng chứng phần Owner login vẫn chưa sửa. Dòng “No write retry” là chú giải chung của Desktop, không xác nhận có thao tác ghi thất bại.

## Kiểm kê đầy đủ backend và DB local cùng Codex
- Đã đối chiếu **6 file SQL migration**, các truy vấn runtime (Codex rà 45 file TypeScript, 177 đoạn SQL và các biến thể query), PostgreSQL 18.4 ở `127.0.0.1:5433/postgres`. Kết quả trước khi sửa: **29/32 bảng, 203/225 cột**, thiếu 1 view; các cột hiện có không phát hiện khác kiểu/default trong phạm vi so sánh, có 1 sai lệch `NOT NULL`. Queue `mita_queue` không thấy drift. Không tuyên bố mọi nhánh runtime đều đã được chạy E2E.
- Chính xác **7 sai lệch gốc** được xác nhận:
  1. `pricing_policy.check_price_expiry` thiếu (`boolean NOT NULL DEFAULT false`).
  2. `pricing_policy.price_expiry_days` thiếu (`integer NOT NULL DEFAULT 1`, CHECK 1–365).
  3. `order_notification_outbox` thiếu (cùng PK/FK/UNIQUE/CHECK, sequence và unread index).
  4. View `amazon_product_metrics` thiếu; catalog và Top Reviews phụ thuộc view này.
  5. `order_items.observed_at` vẫn `NOT NULL`, trong khi SQL/logic hiện tại cho phép `NULL`.
  6. `order_email_delivery_activation` thiếu.
  7. `order_email_deliveries` thiếu (cùng PK/FK/UNIQUE/CHECK, sequence và work index).
- Truy vấn read-only tái hiện **42P01** đối với outbox và view, **42703** với Pricing; `/api/catalog` trước sửa trả HTTP 500. Các index/sequence và constraint đi kèm là **hệ quả của bảng bị thiếu**, không tính thêm lỗi gốc.
- Không dùng `npm run db:migrate` hoặc `scripts/start-local.ps1` để vá vì runner tổng nạp SQL/DML ngoài phạm vi, có thể làm biến đổi trạng thái dữ liệu và Amazon. Không sửa `backend/src/db/migrate.ts` hay `backend/tests/run.ts` vì đã nạp SQL đúng thứ tự. SQL chuẩn nằm ở `backend/src/db/admin.sql:54,57-58`, `schema.sql:251-268`, `order-notifications.sql`, `email-delivery.sql`.
